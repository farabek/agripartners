## 3. Priority Model

- **P1 — Core:** governance, navigation, current roadmap/release authority, architecture, and the
  frozen Business baseline. Never archive.
- **P2 — Active:** current Product, Investor, Farmer, Legal, NEAR, Pilot, Operations, Partnership,
  and CRM work. Review regularly.
- **P3 — Reference:** useful research, technical review, implementation, presentation, translation,
  or supporting material. Keep accessible without granting authority.
- **P4 — Archive:** deprecated, superseded, historical, duplicate, completed-phase, or stale
  generated material. Do not delete.

## 9. Link Migration Risk

- **High:** more than five detected inbound links or a broad entry point.
- **Medium:** one to five detected inbound links.
- **Low:** no detected local Markdown/HTML links.
- **External unknown:** distributed decks, PDFs, bookmarks, and external URLs may reference paths
  that repository scanning cannot detect.

Search the full repository and publication records before each move. Stable paths require an
approved authority migration and compatibility plan.

## 10. Recommended Execution Phases

### Phase 1 — Labels and index only

Add priority, access, canonical, archive-candidate, stable-path, and reading-order labels.

### Phase 2 — Mark deprecated documents

Add replacement links and obtain owner approval for every P4 classification.

### Phase 3 — Move safe archive candidates

Move only low-risk approved candidates with `git mv`; update the archive manifest.

### Phase 4 — Update links

Update inbound links, indexes, generated publications, and required compatibility redirects.

### Phase 5 — Validate repository

Run Markdown lint, local-link validation, full old-path searches, relevant builds, `git diff
--check`, and `git status`.
