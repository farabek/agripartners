# AgriPartners NEAR Use Case

## Why NEAR

AgriPartners uses NEAR because agricultural investment workflows need low-cost transactions, readable accounts, fast finality, and infrastructure that can support real-world asset use cases without making the user experience feel too technical.

NEAR is a strong fit because:

- Transaction costs are low enough for repeated lifecycle events.
- Account-based UX can be explained to non-crypto users.
- Testnet supports fast iteration before mainnet launch.
- The ecosystem has interest in RWA, impact, emerging markets, and practical blockchain adoption.
- Smart contracts can provide an auditable state layer for agricultural deals.

## How Smart Contracts Are Used

The smart contract layer represents the lifecycle of an agricultural investment deal. In the MVP, NEAR Testnet is used to demonstrate contract-aware workflows rather than production financial settlement.

Contract-backed concepts include:

- Deal creation and parameter tracking.
- Funding confirmation.
- Cycle activation.
- Farmer reporting.
- Return recording.
- Withdrawal or settlement-related actions.
- Lifecycle status changes such as active, pending, or completed.

The application translates these events into business-readable language for investors, farmers, and partners.

## Investor Workflow

The investor workflow focuses on clarity and reviewability:

1. Investor accesses the portal through a role-specific account.
2. Investor reviews portfolio metrics and featured pilot deals.
3. Investor opens a pilot project such as Fidlot or Hissar.
4. Investor reviews investment size, ROI, simple annualized ROI, cycle count, expected returns, returned amount, and outstanding amount.
5. Investor follows reporting and event history to understand lifecycle progress.
6. In a future mainnet version, funding and settlement can be connected to audited smart contract flows.

## Farmer Workflow

The farmer workflow focuses on operational visibility:

1. Farmer accesses the portal through a role-specific account.
2. Farmer sees assigned pilot projects.
3. Farmer confirms funding visibility and current cycle status.
4. Farmer tracks active and completed deals.
5. Farmer submits or follows reporting status.
6. Lifecycle events become visible to investors and admins through the shared workflow.

## Reporting Workflow

Reporting is a core trust function. The MVP shows how farm progress can become part of a structured investment record.

The reporting workflow includes:

- Funding confirmed.
- Cycle active.
- Report submitted.
- Next report due.
- Return recorded.
- Pending or completed status.

In the current Alpha v1, this reporting workflow is demonstrated through the product layer and NEAR Testnet lifecycle concepts. Future versions can strengthen verification with project evidence, partner attestations, photos, documents, and on-chain references.

## Future Mainnet Vision

The mainnet vision is to move from controlled Alpha v1 demos to audited, legally structured, production-ready agricultural investment workflows.

Future mainnet milestones include:

- Independent smart contract security audit.
- Legal and compliance review for investment structures.
- Wallet UX improvements for non-technical investors and farmers.
- Audited mainnet deployment.
- First live pilot deals with documented partner validation.
- Stronger evidence package for farm operations.
- Transparent settlement and withdrawal workflows.
- Scalable templates for additional livestock and agricultural models.

The long-term opportunity is to make NEAR a practical infrastructure layer for real-world agricultural finance in emerging markets.
