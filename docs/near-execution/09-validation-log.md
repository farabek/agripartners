# Validation Log

## Purpose

This document provides a structured validation feedback system for real AgriPartners ecosystem conversations.

The validation log should track what was discussed, what feedback was received, what concerns appeared, and what next action is required. It is designed for NEAR ecosystem conversations, accelerator discussions, ecosystem partner conversations, investor-readiness review, and regional validation.

This document is a template only. It does not include contacts, personal names, contact research, outreach activity, commits, pushes, or implementation changes.

## Validation Statuses

### Planned

The organization or category is relevant, but no outreach has been completed.

### Contacted

The first message or introduction has been sent.

### Conversation Held

A real conversation, meeting, call, or substantive reply has happened.

### Follow-up

AgriPartners needs to send additional materials, clarification, answers, or updated documents.

### Application Submitted

An accelerator, program, grant, or partner application has been submitted.

### Partnership Discussion

The conversation has moved from feedback into a possible collaboration path.

### Closed

The validation item is complete, low fit, inactive, or no longer relevant.

## Field Guidance

### Date

Use the date of the conversation or latest meaningful update.

### Organization

Use an organization name only when already known through user-provided context or existing planning. Do not conduct contact research.

### Person / Team

Use a team, role, or generic contact label. Personal names are not required.

Examples:

- Ecosystem team.
- Accelerator review team.
- Technical reviewer.
- Partnership team.
- Investor team.

### Channel

Recommended channels:

- Email.
- Call.
- Meeting.
- Event.
- Intro.
- Application.
- Community channel.

### Materials Sent

Track only the materials that were actually sent or shown.

Recommended materials:

- Intro message.
- Project summary.
- NEAR use case.
- Ecosystem one-pager.
- Investor deck.
- Demo screenshots.
- Demo script.
- Technical notes.

### Demo Shown

Use simple values:

- Yes.
- No.
- Partial.
- Scheduled.

### Key Discussion Points

Summarize the main topics discussed.

Useful examples:

- NEAR ecosystem fit.
- Central Asia agriculture relevance.
- Farmer financing workflow.
- Investor transparency.
- ROI and returns tracking.
- Reporting workflow.
- Smart contract readiness.
- Accelerator readiness.
- Partnership scope.

### Positive Feedback

Capture validation signals.

Useful examples:

- The use case is understandable.
- The demo is clear.
- Reporting workflow is valuable.
- NEAR integration direction makes sense.
- Regional agriculture angle is relevant.
- Partnership category is promising.

### Concerns

Capture blockers and risks.

Useful examples:

- Mainnet readiness unclear.
- Legal structure needs review.
- Farmer adoption evidence is limited.
- Technical architecture needs review.
- ROI language needs more caution.
- Materials need stronger proof.

### Questions Asked

Record questions from the reviewer or partner.

Useful examples:

- What is on-chain today?
- What is still simulated?
- What legal structure is planned?
- How are farmer reports verified?
- What is the mainnet path?
- What evidence supports pilot results?

### Next Action

Define one concrete next action.

Examples:

- Send follow-up.
- Send demo screenshots.
- Update NEAR use case.
- Prepare technical review notes.
- Submit application.
- Schedule next meeting.
- Move to partnership discussion.
- Close as low fit.

### Owner

Use a role or internal owner label. Personal names are not required.

Examples:

- Founder.
- Product.
- Technical.
- Partnerships.
- Operations.

## Monthly Review

Use this review at the end of each month.

### What Worked

- Which conversations produced the strongest validation?
- Which materials were most useful?
- Which categories understood the project fastest?
- Which demo moments created the clearest signal?

### What Failed

- Which messages did not create useful replies?
- Which materials were unclear?
- Which categories were low fit?
- Which assumptions were challenged?

### What Repeated

- Which questions came up multiple times?
- Which concerns repeated across categories?
- Which positive signals appeared more than once?
- Which material requests repeated?

### What Should Change

- Which narrative should be updated?
- Which screenshots or demo assets should be improved?
- Which technical notes should be added?
- Which category should be prioritized next?
- Which outreach path should be paused?
